# Implementation plan

Goal: build a reproducible benchmark that can test the delegation hypotheses without assuming they are true.

1. **Done:** Initialize the Rust project and document protocol gates. Check: `cargo test` — 3 tests passed.
2. **Done:** Implement deterministic datasets and independently scored artifacts. Check: `cargo test --locked -- --nocapture` — 11 tests passed in 56.09s. The suite test validates two identical 48-task generations, row counts, 48 accepted reference trees, 48 rejected unauthorized files and 48 rejected corrupted artifacts. All four families include explicit expected failures. Artifact sizes are checked against recorded limits; runtime and memory enforcement are part of step 3. Semantic unit tests independently check timestamps, ties, text boundaries, numeric aggregation and precision. See tasks/README.md for commands and independence limitations. Suite v2 remains unfrozen until pilot review.
3. **Done:** Implement isolated execution, independent feedback verification, and bounded certificates. Check: `cargo test --locked -- --nocapture` — 17 unit tests passed (90.12s) plus 1 real CLI integration test (3.38s); `cargo fmt --check` and `cargo clippy --locked --all-targets -- -D warnings` pass. Tests cover allowlist rejection, namespace identity, host-file isolation, network isolation, read-only runtime, timeouts, hard resource limits, process/thread denial, workspace budgets, symlink rejection, output counters, certificate bounds, full-suite oracle/verifier agreement, and B/C/D rendering. See docs/execution.md. Supported boundary: Linux x86_64, single-process tools, sampled workspace budgets (not hard disk quotas); no unsandboxed fallback. Model treatment arms and token telemetry remain step 4.
4. **Offline core complete; real-provider validation pending:** Implement model integration, four arms, and run-level telemetry. Acceptance: `TMPDIR=/tmp/opencode cargo test --locked -- --nocapture` — 20 unit tests (90.66s), 4 orchestrator CLI tests (2.61s), and 1 sandbox CLI test (3.41s) passed; formatting and Clippy with warnings denied pass. Includes replay and trusted-connector interfaces, strict actions, chunked direct sinks, B/C/D command batches and feedback, isolated final scoring, bounded retries/resources, API-usage accounting, JSONL traces/records and a reproducible 576-entry schedule. No real provider was selected or contacted. Per-message tokenization and attribution calibration remain unresolved until a provider connector is selected; unknown values are null. This is not approval to run a pilot. See docs/model-runs.md.
5. **Done (exploratory engine):** Implement paired analysis and report generation. Acceptance: `TMPDIR=/tmp/opencode cargo test --locked -- --nocapture` — 30 unit tests (90.69s) and 8 CLI integration tests (0.15s + 4.34s + 3.45s) passed. Includes byte-identical report regeneration from saved JSONL, seven SVG charts, zero-success handling, negative token savings, task-cluster (not repetition-level) bootstrap, independent correctness non-inferiority, size/family/complexity/outcome interactions and in-range crossovers, observed invocation relationships, interrupted-run recovery, verifier error rates and trace-based failure categories. Invalid/mixed/duplicate cohorts are rejected; failures, unknown usage and missing cells remain explicit. Formatting and Clippy with warnings denied pass. Tests use artificial accounting fixtures only. All current reports remain exploratory; margin/method approval and confirmatory protocol binding remain future work before the main study. See docs/analysis.md.
6. Run the pilot after deterministic tests pass, GPT-6 Luna subscription access is verified, and token accounting and usage limits are configured. Pricing is deferred by user request; monetary cost remains null. Check: 40 real pilot runs and their traces are recorded; repair defects before proceeding.
   - Accounting: `luna-connector` targets the ChatGPT Codex Responses endpoint with the live OAuth credential from the OpenCode credential broker and rejects replies without provider-reported usage. A live probe returned `input_tokens=28`, `output_tokens=7`, `cached_tokens=0`, resolved model `gpt-6-luna` and `finish_reason=stop`. The endpoint rejects `temperature` for this model and applies `temperature=1.0`, `top_p=0.98` itself; pinned decoding omits temperature. Evidence: reports/luna-connector-probe.json. Transport is also tested against a local mock server (`cargo test --locked --test luna_connector`).
   - Executor: `pilot-plan` writes the randomized 40-run matrix without spending quota; `pilot-run` executes it with fresh run directories, protocol locking, crash recovery from `summary.json`, retry-in-a-new-attempt after quota blocks, and stops on quota, setup errors or three consecutive adapter failures. Records and limits: docs/pilot.md. Tests: `cargo test --locked --test pilot_cli` (all four arms through the real sandbox/score path against a provider double; quota stop/resume; configuration drift) and the pilot unit test.
   - Smoke test: all four arms now run live on `sorting-v0-s0`. B and C succeeded with 5 calls each (6,599 and 7,191 tokens); D succeeded with 5 calls (3,933 tokens) and verifier/oracle agreement; A's interface worked (read, complete put, submit, finish in 5 calls, 6,186 tokens) but the model wrote a wrongly ordered artifact, so the oracle rejected it. Five interface defects were found and fixed: missing schema forwarding, ambiguous schema shape, hidden read cap, rejections without reasons, and unclear arm-A put/submit semantics. Evidence: reports/smoke-run.json. Not part of the pilot matrix.
   - Remaining pilot prerequisites: record ChatGPT Plus usage limits, resolve per-message feedback attribution (provider returns `usage.attribution`, unused so far), and execute the 40 runs. No pilot runs started.
7. Freeze the main protocol and run the main experiment only after pilot review and usage-limit approval. Pricing remains optional while deferred. Check: 576 or more run records and a reproducible report exist.

Plan review: execution isolation must be established rather than assumed, model token accounting must use provider-reported usage, and the independent oracle must not share the feedback verifier's implementation. API access and expenditure are not assumed. No real-model measurements are available until those prerequisites are met.
